# Одна основа для клиентских сайтов: промпты для Claude Code

## Как пользоваться

1. Создай на GitHub пустой репозиторий `site-core`. В настройках отметь **Template repository**. Это основа, из неё потом рождается каждый клиентский сайт кнопкой «Use this template».
2. `ellischmentsbrain` остаётся твоим собственным сайтом и собирается из основы после этапа 9, как первый «клиент».
3. Склонируй `site-core` и положи рядом «Принца и Лиса»:
   ```
   work/
     site-core/        ← здесь работаем
     prince-u-lis/     ← только читаем
   ```
4. Этот файл положи в `site-core/docs/PROMPTS-CORE.md`. Тогда в каждой новой сессии достаточно написать: «Выполни этап 3 из docs/PROMPTS-CORE.md».
5. Один этап = одна сессия. Этап закрыт, когда `npm run check` зелёный и сделан коммит. Следующий этап не начинать с красной проверкой.

Порядок: 0 → 9 для основы, дальше промпты под конкретных клиентов.

## Этап 6. Выкладка на дешёвый сервер

```text
Прочитай CLAUDE.md, STATE.md и ../prince-u-lis/DEPLOY.md.

Перенеси и сделай параметризуемой инфраструктуру. Целевой сервер: 1 ядро, 1 ГБ памяти, 10 ГБ диска, Ubuntu 24.04, сборка идёт на самом сервере.

1. Dockerfile: standalone, отдельная стадия сборки с NODE_OPTIONS=--max-old-space-size=1024, итоговый образ минимальный.
2. docker-compose.yml: лимиты памяти около 600m приложению и 128m Caddy, том для базы и загрузок.
3. Caddyfile строится из доменов в client.config.ts (скрипт scripts/gen-caddyfile.ts), автоматический сертификат.
4. scripts/deploy.sh: копия базы до выкатки, запоминание коммита для отката, сборка, ожидание готовности, docker builder prune и image prune после успешной выкатки. rollback.sh, backup.sh, restore-check.sh.
5. scripts/server-setup.sh для чистого сервера: пользователь без root, SSH только по ключу, файрвол (22, 80, 443), swap 2 ГБ, Docker, cron для backup и /api/cron.
6. .github/workflows/check.yml: типы, линтер, юнит-тесты на каждом пуше, чтобы сервер не тратил память на проверки.
7. DEPLOY.md пошагово для человека, который первый раз видит сервер: от покупки VPS и настройки DNS до первой выкатки и отката. Отдельный раздел «если сборка не помещается в память»: собрать локально и перенести образ через docker save | ssh docker load.

Проверь сборку в контейнере с ограничением памяти 1 ГБ. Запиши в STATE.md, сколько памяти и времени заняла сборка.
Коммит: «Выкладка на сервер 1 ГБ».
```

## Клиенты на основе

Промпты под конкретных клиентов хранятся вне репозитория, пока он публичный: в них имена и цифры заказчиков.
