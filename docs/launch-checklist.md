# Чек-лист запуска клиента

Каждый пункт проверяется командой или руками, результат пишется в `STATE.md`.

## До выкладки

- [ ] `npm run check` зелёный.
- [ ] `client.config.ts`: название, реквизиты, контакты, домены, модули заполнены.
- [ ] Политика ПДн и согласие показывают реквизиты заказчика, а не заглушки.
- [ ] Раздел «Готовность» в админке без красных пунктов или они в `docs/waiting-for-client.md`.
- [ ] `.env.example` соответствует `lib/env.ts`.

## Сервер

- [ ] DNS: A `@` и `www` на IP сервера (`dig +short <домен>`).
- [ ] `server-setup.sh` выполнен, root по SSH закрыт, ufw 22/80/443.
- [ ] `/srv/<клиент>/.env` с правами 600.
- [ ] `bash scripts/deploy.sh` прошёл, `docker stats --no-stream` меньше 600 МБ.
- [ ] Cron: ночной `backup.sh`, ежемесячный `restore-check.sh`, `/api/cron` раз в час.

## После выкладки

- [ ] `curl -sI https://<домен>` отдаёт 200 и шесть заголовков безопасности.
- [ ] `https://www.<домен>` перенаправляет на основной адрес.
- [ ] `https://<домен>/admin` просит вход, пять неверных паролей блокируют адрес.
- [ ] Тестовая заявка: пришла в админку, уведомление в Telegram без персональных данных.
- [ ] `robots.txt` и `sitemap.xml` открываются, в sitemap нет выключенных модулей.
- [ ] Яндекс Вебмастер: сайт подтверждён, sitemap добавлен.
- [ ] Бэкап появился в `/srv/backups`, восстановление проверено `restore-check.sh`.
- [ ] Владелец получил пароль и инструкцию, пароль сменён после первого входа.
